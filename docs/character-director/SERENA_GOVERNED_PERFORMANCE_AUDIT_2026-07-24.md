# Serena Governed Performance Audit

Date: 2026-07-24

## Verdict

The smallest truthful next gate is `Serena G1: Governed Speech and Static Score
Parity`. It excludes locomotion, flight, arbitrary music choreography,
production registry admission, and visual permission-world parity.

## Blocking Findings

1. Media-session admission did not compare the incoming character and package
   identity to the active runtime before coordinator and scheduler mutation.
2. `PerformanceApplication` created `ScoreRuntime` without the loaded
   package's verified package, pose-library, graph, preload, clip, and node
   admission identities. The capability-manifest digest belongs to the
   compilation/context boundary because compiled-score schema V1 does not
   carry it.
3. The Prism main-media slot still needs to consume the same active performance
   binding already used by governed speech.
4. Serena currently has no permission-world surface vocabulary; this is safely
   fail-closed but not visual parity.
5. Governed-speech generation and revocation precision remain later G1 work.

## Implemented Foundation

- Serena's package, runtime profile, capability profile, pose manifest, graph,
  pose library, and pixel graphs are hash verified.
- Static actions, eight facings, blink, and seven speech shapes are
  package-driven.
- Unsupported Wizard actions and locomotion fail without state mutation.
- Governed speech already binds content, context, character, package, media,
  alignment, reconciliation, and revocation evidence.

## Ordered G1 Plan

1. Reject foreign character or package snapshots before all runtime mutation.
2. Bind score admission to canonical compiled-score fields: character,
   package, pose-library and graph digests, cue clip/node IDs, and cue
   `preload_asset_ids`.
3. Hydrate main and speech connector slots from one active performance binding.
4. Bind governed-speech evaluation and revocation to the current generation.
5. Author one Serena-only static score using admitted action and pose IDs.
6. Prove interruption, stale-input, accessibility, replay, and Wizard
   regression behavior.

Every accepted checkpoint must record the exact commit and package digest.
